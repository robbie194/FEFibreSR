# 关于 GRIN 模糊、时间步长、APS 积分和事件极性的四个问题

本文针对当前配置：

```yaml
grin:
  fibre_grid_pixel_size_um: 0.5
  sigma_um: 0.0

motion:
  velocity_um_s: [180.0, 0.0]
  duration_s: 0.025
  dt_s: 0.0001
```

以及 2026-08-14 重新生成的 `outputs/phase1_usaf` 结果进行回答。文中的数值结论来自 HDF5/NPY 原始数组，不是根据 PNG 预览图估计。

## 问题 1

> `sigma_um: 0.0` 这里为 0，是不是就意味着得到的 GRIN 都和原 input 一样清晰？

### 回答

基本理解正确，但需要限定“哪一级”和“是否完全相同”。

当前 [grin.py](src/fibre_sim/grin.py) 中的 `sigma_um` 只控制 GRIN 这一级额外施加的 Gaussian 模糊：

```python
if sigma_um > 0:
    frame = cv2.GaussianBlur(...)
```

因此当 `sigma_um=0.0` 时：

- GRIN 模块不额外施加 Gaussian PSF；
- 在光学清晰度意义上，GRIN 输出保留输入图案的清晰程度；
- 它仍会根据运动、放大率和视场执行坐标重采样及裁剪；
- 后续纤芯圆孔面积平均、蜂窝采样和 DAVIS 像元面积积分仍会损失空间信息。

所以不能把它理解成“最终 sensor image 与原始 input 完全相同”。更准确的说法是：

> `sigma_um=0` 关闭了 GRIN 这一层的人为 Gaussian 模糊，但没有关闭运动、裁剪、纤芯有限孔径、离散采样和 sensor pixel integration。

### 当前数据的直接验证

在 `t=0`、`magnification=1`、`transmission=1` 的当前配置下，GRIN 的 320 x 320 输出恰好对应 400 x 400 input 的中央 320 x 320 区域。数组核验结果为：

```text
max_abs(grin[0] - input_center_crop) = 0.0
mean_abs(grin[0] - input_center_crop) = 0.0
```

这说明当前 `t=0` GRIN 输出确实是 input 中央区域的无额外模糊裁剪。

但在 `t>0` 时，输出是 input 的亚像素平移采样，不会与 `t=0` 数组相同。到 fibre 和 sensor 阶段后，也会继续受到各级采样算子的影响。

### 另一个容易混淆的参数

配置里还有：

```yaml
relay:
  psf_sigma_sensor_um: 0.0
```

它控制的是中继成像在 sensor plane 上的额外 Gaussian PSF，与 `grin.sigma_um` 不是同一个参数。二者都为 0 时，仍然保留 fibre aperture 和 sensor pixel integration。

### 这个参数以后应该怎样设

- 做最小闭环和数值排错时，可以设为 0，避免模型中混入未经标定的模糊。
- 做接近真实硬件的仿真时，不应凭经验随意指定，优先使用实测 GRIN/远端成像 PSF 拟合出的值。
- 做消融实验时，可分别比较 `0.0`、`0.4`、`0.8 um` 等设置对事件数量和重建上限的影响。

## 问题 2

> 0.1 ms 为最小时间吗？空间的最小分辨率网格为 1 um，那么相邻两个 frame 的位移小于 1 um，相邻两张会不会一样，无法表示出位移？

### 回答

`0.1 ms` 不是程序或事件相机的固有最小时间，它只是当前前向强度序列的配置采样间隔：

```yaml
motion.dt_s: 0.0001
```

它可以继续减小，例如 `0.05 ms` 或 `0.01 ms`，代价是瞬时帧数量、HDF5 大小、运行时间和显存/内存占用增加。

此外，当前空间网格不是 1 um，而是：

```yaml
source.pixel_size_um: 0.5
grin.fibre_grid_pixel_size_um: 0.5
```

当前相邻时间样本的物理位移为：

$$
\Delta x
=180\ \mathrm{um/s}\times0.0001\ \mathrm{s}
=0.018\ \mathrm{um}.
$$

换算到 0.5 um/px 网格：

$$
\Delta x_{grid}=\frac{0.018}{0.5}=0.036\ \mathrm{px}.
$$

### 小于一个像素的位移能否表示

可以。图像网格是像素值的采样位置，不代表运动只能按整数像素跳动。[grin.py](src/fibre_sim/grin.py) 使用浮点 `map_x/map_y` 和双线性重采样，所以能够表示小数像素位移。

相邻两帧虽然肉眼很难区分，但数组值会有小幅连续变化。当前 250 对相邻帧的实际核验结果为：

| 序列 | 相邻帧 MAE 最小值 | 中位数 | 最大值 | 完全相同的相邻帧对 |
|---|---:|---:|---:|---:|
| GRIN | 0.000952 | 0.000966 | 0.001950 | 0 |
| Sensor | 0.000157 | 0.000167 | 0.000353 | 0 |

GRIN 相邻帧的最大单像素变化在不同时间约为 `0.0279-0.0559`；sensor 相邻帧最大变化约为 `0.00550-0.01119`。因此当前数据不存在“相邻两张完全一样而无法表达运动”的问题。

### 需要注意的数值边界

亚像素重采样仍然是离散数值近似，不等于无限精度连续光学传播。位移继续减小时可能受到：

- OpenCV 插值表精度；
- float32 数值精度；
- 输入图像局部是否平坦；
- 后续纤芯孔径平均和 sensor pixel integration；
- v2e 对比度阈值。

即使相邻帧数值不同，变化也未必大到足以越过事件阈值。因此应区分：

1. **运动能否在瞬时强度数组中表示**；
2. **累计变化能否触发事件**。

当前第一点已经满足；第二点取决于若干时间步累计后的 log-intensity 变化，而不是要求每 0.1 ms 都必须产生事件。

### 0.1 ms 是否足够

对当前 180 um/s 匀速基线，0.1 ms 足以生成平滑变化并通过基本检查。但它不是自动可信的最终选择。正确做法是执行时间步长收敛实验：

```text
dt = 0.2, 0.1, 0.05, 0.025 ms
```

比较 APS 差异、事件总数、事件时刻分布和最终重建指标，直到继续减小 `dt` 不再显著改变结论。

## 问题 3

> `comparison.png` 中积分累加的结果看起来和单帧差不多，代码确认是对的吗？

### 回答

代码的积分实现是正确的。这里执行的不是简单“累加”，而是曝光时间平均：

$$
B=\frac{1}{T}\int_{t_0}^{t_1}I(t)\,dt.
$$

[aps.py](src/fibre_sim/aps.py) 会：

1. 取真实曝光起止时间；
2. 如果曝光边界不在已有采样点上，就先做时间插值；
3. 使用所有曝光内端点做梯形积分；
4. 除以曝光长度，得到平均辐照度。

### 独立数值复算

直接从 `sensor_sequence.h5` 重新执行：

```python
np.trapz(sensor_frames, x=timestamps, axis=0) / exposure_duration
```

与保存的 `aps_frame.npy` 比较得到：

```text
maximum absolute error = 2.98e-8
mean absolute error    = 2.04e-9
```

这个误差只在 float32 舍入量级，说明保存的 APS 与独立梯形积分一致。

### 为什么肉眼看起来相似

原因有四个：

1. `comparison.png` 三幅图都固定使用 `[0,1]` 灰度范围，局部差异不会被单独放大。
2. 整幅画面由大量位置固定的明亮芯斑和黑色间隙主导，蜂窝结构在三幅图中完全相同。
3. 当前是匀速、对称曝光，时间平均天然接近曝光中心 `12.5 ms` 的瞬时状态，只是在变化区域发生平滑。
4. 运动总量是一个芯间距，但物体结构经过 2.9 um 圆孔平均，很多宽线条区域在曝光期间变化不大。

当前 APS 与三张瞬时帧的数值比较为：

| 参考瞬时帧 | MAE | RMSE | 最大绝对差 | 相关系数 |
|---|---:|---:|---:|---:|
| 0 ms | 0.01846 | 0.06561 | 0.53988 | 0.97857 |
| 12.5 ms | 0.00614 | 0.02188 | 0.26378 | 0.99764 |
| 25 ms | 0.01916 | 0.06737 | 0.55732 | 0.97729 |

这正好说明：APS 和中间瞬时帧非常相似，但不是相同；与曝光两端的差异更明显。

相对于 12.5 ms 瞬时帧，约 `16.1%` 的 sensor pixels 差异超过一个 8-bit 灰度级 `1/255`。这些差异在 `difference_vs_middle.png` 中经过自动缩放后可以清楚看到。

### 预览图还可以怎样改进

当前 `comparison.png` 适合看整体结构，但不适合判断微弱曝光模糊。以后可以额外保存：

- APS 与 0/12.5/25 ms 帧的 signed difference；
- 局部 ROI 放大图；
- 水平强度剖面；
- 每幅图之间的 MAE、RMSE 和相关系数。

这属于诊断展示增强，不影响当前 APS 数值结果的正确性。

## 问题 4

> 我理解画面是整体运动的，为什么事件图 `segment_02_0002.0_0003.0ms.png` 中，有的芯全是正、有的芯全是负，有的事件在纤芯边缘？是不是调用 v2e 的方式不对？

### 回答

在当前前向模型的物理坐标中，这个现象是合理的。关键是要区分远端物体平面和近端 sensor 平面。

### 当前模型中究竟什么在移动

当前运动发生在：

```text
远端物体图案 相对 固定纤芯阵列移动
```

每根纤芯的物理位置固定，它对移动物体做圆孔面积平均，因此变化的是每根芯的标量强度 `core_signals[t,i]`。随后这些标量被渲染到固定的芯斑位置，再中继到固定 DAVIS pixels。

所以 sensor plane 的现象更接近：

```text
固定位置的芯斑随物体经过而变亮或变暗
```

而不是普通相机中：

```text
一幅连续图像的边缘整体横向滑过 sensor
```

因此在一个 1 ms 窗口内：

- 某根芯的采样区域整体变亮时，该芯斑会产生一组 ON events；
- 某根芯的采样区域整体变暗时，该芯斑会产生一组 OFF events；
- 位于平坦区域、累计变化未越过阈值的芯不产生事件。

这就是为什么看起来有的芯几乎全红、有的芯几乎全蓝。

### 为什么事件会出现在芯斑边缘

v2e 是逐 sensor pixel 触发的，不是逐纤芯触发的。一个芯斑覆盖约 4.71 sensor pixels 的直径，边缘 pixels 只接收到部分芯斑面积，并经过：

- fibre 出射圆斑渲染；
- 中继的双线性重采样；
- `2 x 2` sensor 子像素面积平均；
- v2e 的 lin-log 响应和逐像素阈值判断。

因此在**当前数值模型**中，事件可能沿固定芯斑的像素轮廓出现。特别是在低强度边缘，v2e 的 lin-log 转换不是理想纯 log 比例；不同 sensor pixels 还各自维护事件参考值，所以边缘 pixel 与中心 pixel 不一定在完全相同的时间窗内越过阈值。

这不等价于芯斑本身在 sensor 上移动，也不自动表示 v2e 坐标错误。但圆环的精确空间形状来自当前固定圆斑渲染和 DAVIS 像素采样，不能直接解释为远端纤芯内部发生变化的位置。

### 新的追问：只有周围一圈有事件，是否具有真实的纤芯内部空间含义

> 有的纤芯只有周围一圈有事件。这是不是只能说明该纤芯只产生了少量事件？圆环位置本身是否不是真实可解释的位置？因为单根纤芯传递时会发生模式变化，同一纤芯内的入射位置和出射位置无法一一对应，对吗？

这个判断的核心是正确的，需要把“sensor pixel 地址”和“远端纤芯内部坐标”分开。

#### 当前代码先把一根纤芯压缩成一个标量

当前 [fibre.py](src/fibre_sim/fibre.py) 对每根纤芯入口圆孔内的强度做面积平均，得到：

$$
c_i(t)=\frac{1}{|A_i|}\int_{A_i}J(\mathbf u,t)\,d\mathbf u.
$$

这里的 $c_i(t)$ 对第 $i$ 根纤芯来说只是一个随时间变化的标量。随后代码把这个标量乘到一个固定圆斑上：

$$
F(\mathbf z,t)=\sum_i c_i(t)P_i(\mathbf z-\mathbf r_i),
$$

其中当前 $P_i$ 是按圆形覆盖核生成的固定空间轮廓。也就是说，代码已经在入口面积平均时丢掉了“光从纤芯内哪个子位置进入”的信息；近端圆斑内部的多个 DAVIS pixels 只是同一个 $c_i(t)$ 经过固定 $P_i$ 展开后的多个读出位置。

因此：

- 圆环上的坐标是真实的**模拟 DAVIS sensor pixel 坐标**；
- 它不是远端纤芯入口截面中对应点的坐标；
- 不能说圆环某一点对应远端纤芯内同一方位的入射点；
- 也不能把一个芯斑覆盖的多个 event pixels 当成多个独立的远端空间采样。

#### “只有一圈”具体说明什么

它严格说明的是：在该 1 ms 显示窗口内，只有芯斑轮廓附近的部分 DAVIS pixels 越过了各自的事件阈值。

它不直接说明：

- 远端物体只在纤芯圆孔边缘发生了变化；
- 光只从纤芯边缘传播；
- 圆环保留了入射位置；
- 这根芯拥有一圈独立的空间分辨率。

从 core-domain 角度看，可以把它概括成“这根芯在该窗口产生了一部分 sensor-pixel events”，但 event 数量必须对该芯斑覆盖的所有 sensor pixels 做聚合后才能确定。仅凭 PNG 中看到一圈，不能可靠判断事件总数，因为同一个 pixel 可能在窗口内触发多次，而预览图还使用了 log count 显示。

当前模型中出现“中心没有、边缘有”的时间切片，可能来自：

- 中心与边缘的基准强度不同；
- v2e 在低强度处使用 lin-log 响应；
- 每个 DAVIS pixel 的上一次事件参考状态不同；
- 一个 1 ms 分段恰好截取了边缘 pixels 越阈值的时刻，而中心 pixels 已在前一段触发或要到后一段才触发；
- 固定圆斑经过中继插值和像元面积积分后的离散轮廓。

这些都是当前 sensor-readout 模型中的阈值时序现象，而不是纤芯内部空间成像。

#### 真实纤芯中的模式传播是否保留位置对应

通常不能假设一一对应。输入到单根纤芯的场会投影到它支持的导模，传播后各模式积累不同相位并在输出端叠加。概念上可写成：

$$
E_{out,i}(\mathbf z,t)
=\sum_m a_{i,m}(t)\psi_{i,m}(\mathbf z)e^{j\beta_{i,m}L}.
$$

输出强度为 $|E_{out,i}|^2$。入射位置、角度、偏振、波长、纤芯弯曲和模式耦合都可能改变系数 $a_{i,m}$，所以输出端模式或 speckle 结构通常不能按几何位置反查到同一入射子位置。

即使某根芯接近单模，输出也通常表现为固定模式轮廓乘一个耦合振幅；这仍不表示入口截面与出口截面存在逐点成像关系。对多模芯，这种逐点对应更不能默认成立。

照明相干性也很重要：相干照明下模式干涉和 speckle 更明显；宽带或空间非相干照明会平均掉部分干涉结构，但不会自动恢复入口到出口的逐点映射。

所以你的结论可以准确表述为：

> 一根纤芯首先是一个有限孔径、有限模式的传输通道，而不是一根能够对纤芯截面内部进行逐点成像的小相机。没有 transmission matrix 或逐芯标定时，近端芯斑内部位置不能解释为远端入射位置。

#### 当前圆斑模型是否因此完全错误

不是完全错误，但它只是一阶简化。它表达的是：

1. 每根芯输出一个标量强度；
2. 该强度通过固定近端 spot profile 被 DAVIS 多个 pixels 读取。

这适合验证整体 frame/event 前向链路。但当前使用理想圆盘作为 $P_i$，没有模拟：

- 每根芯真实的近场模式轮廓；
- 输入位置/角度改变引起的输出模式变化；
- 相干模式干涉和 speckle；
- 弯曲、偏振和芯间耦合；
- 每芯不同的 PSF、增益和坏芯。

因此当前事件图可以用于检查时间、极性、sensor 地址和事件数量，但不应把圆环的具体形态当成真实光纤必然产生的模式图案。

#### 后续建议怎样表示和建模

如果第一阶段仍采用“每芯一个标量”的模型，建议同时保留两类结果：

1. **sensor-plane event map**：保留真实 DAVIS pixel 地址，用于检查传感器读出和 v2e；明确标注它是近端芯斑的像素化结果。
2. **core-domain event summary**：利用 core-to-sensor 区域映射，把每根芯覆盖区域内的 ON/OFF 数量分别聚合，输出 $N_i^+$、$N_i^-$ 或 signed count；用于避免把同一根芯的多个 pixels 误当成多个独立物体采样。

如果要提高近端事件形态的真实性，应按优先级加入：

1. 实测每根芯在 DAVIS 上的固定输出 PSF $P_i$；
2. 每芯 gain、背景、坏芯和 sensor flat-field；
3. 若实验观察到明显随输入变化的模式图案，再引入 mode-dependent PSF 或实测 transmission matrix；
4. 根据实际光源相干性决定是否必须进行复场和模式干涉建模。

在没有这些标定前，最稳妥的逆问题做法是把同一芯斑内的 sensor pixels 视为对同一个 core signal 的冗余读出，而不是独立的亚纤芯空间信息。

### v2e 调用链是否正确

当前 [events.py](src/fibre_sim/events.py) 的调用顺序是合理的：

1. 读取完整的 `[T,H,W]` sensor float32 强度序列；
2. 保持原始递增 timestamps；
3. 将 `[0,1]` 线性强度缩放到 v2e 使用的 `[0,255]` 输入范围；
4. 按时间顺序逐帧调用 `EventEmulator.generate_events(frame,timestamp)`；
5. 保留 v2e 返回的 `[t,x,y,p]`；
6. 最后按时间稳定排序并写入 HDF5。

现有单元测试还验证了：静态序列不产生事件；先变亮再变暗的序列同时产生 ON/OFF events。

### 对 2-3 ms 分段的数值核验

对 `segment_02_0002.0_0003.0ms.png` 对应原始事件执行了独立检查：

```text
segment event count                         = 2869
active sensor pixels                        = 2742
sign(signed event count) 与 sign(delta log I) 一致率 = 100%
corr(signed event count, delta log I)        = 0.9442
```

也就是说，这个时间段中：

- ON events 出现在强度上升的位置；
- OFF events 出现在强度下降的位置；
- 事件符号与 sensor sequence 的实际亮度变化高度一致。

因此没有数值证据表明当前 v2e 调用方式错误。

### 什么情况下你的“整体移动事件边缘”预期才是正确的

如果真实实验是以下运动：

- 近端光纤端面相对 DAVIS 发生机械平移；
- 中继相机或传感器相对近端芯斑阵列移动；
- 整个光纤输出像在 sensor plane 上发生漂移；

那么 sensor 上的芯斑位置确实应该移动，事件也会更多地沿移动芯斑的前后边缘出现。

但当前代码没有模拟这种“近端图像相对 sensor 的运动”。它模拟的是“远端物体相对固定纤芯阵列的运动”。如果实际装置属于前一种情况，需要修改 relay/sensor forward model，而不是修改 v2e 的调用方式。

### 对后续 NeuroSR 的影响

这个区别非常重要。普通 NeuroSR/IWE 常假设 sensor image feature 随运动发生空间位移；当前多芯光纤 sensor 图中，芯斑地址固定而亮度变化。直接把普通平移 warp 套到这些事件坐标上，物理上未必成立。

后续应明确选择：

1. 在 core-domain 中根据已知物体-纤芯相对运动建立事件约束；或
2. 构建包含固定 core sampling 的 fibre-aware forward/event operator；或
3. 如果真实硬件运动确实发生在 sensor plane，则在前向模型中显式加入近端图像平移。

## 总结

1. `grin.sigma_um=0` 表示 GRIN 级不额外加 Gaussian 模糊；当前 `t=0` GRIN 输出与 input 中央裁剪逐值相同，但后续纤芯和 sensor 仍会降低信息。
2. `0.1 ms` 只是当前采样步长，不是最小时间；每步位移为 `0.018 um = 0.036 grid px`，双线性重采样可以表达，实际没有相邻帧完全相同。
3. APS 梯形时间平均代码正确；它在视觉上接近中间瞬时帧是匀速对称曝光的预期结果，差异数组并不为零。
4. 固定芯斑出现整芯 ON/OFF 和边缘事件符合当前“远端物体移动、近端芯位固定”的模型；事件极性与强度变化数值一致，v2e 调用没有显示出错误。
5. 芯斑圆环是当前 DAVIS plane 的事件地址，但不对应远端纤芯内部的同一位置；在标量 core 模型下，同一芯斑内的多个 pixels 是冗余读出，不能当作独立的亚纤芯空间信息。
