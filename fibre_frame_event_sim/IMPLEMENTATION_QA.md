# 多芯光纤 Frame-Event 前向仿真实现问答汇总

本文把 `fibre_frame_event_sim` 完成后集中讨论过的疑问按主题重新整理。问题措辞经过归纳，回答以当前代码、配置和已生成结果为准；早期方案中尚未实现的设想不会写成当前功能。

## 一、项目范围

### Q1：这个目录现在完成了什么？

它完成的是一条可重复运行的**前向数据生成链路**：

```text
USAF 物体
  -> 连续平移
  -> 简化 GRIN 成像
  -> 多芯光纤采样和出射端渲染
  -> 中继成像及 DAVIS 像素积分
  -> APS 曝光积分
  -> v2e 事件生成
```

当前输出包括一张 APS 模糊帧、一条与它时间对齐的事件流，以及每一级中间结果。

它目前**没有实现**：

- NeuroSR 或其他逆问题重建；
- 未知运动估计；
- 真实光纤端面标定；
- 光子噪声、坏芯、芯间串扰和传感器非理想性的完整建模；
- 直接输出可被 `NeuroSRM_demo.py` 读取的 AEDAT4 文件。

### Q2：为什么要把前向仿真拆成 00-07 八个步骤？

每一步都保存中间结果，目的是让物理错误可以被定位。例如，最终事件异常时，可以依次检查：

1. 输入裁剪是否正确；
2. 运动方向和单位是否正确；
3. GRIN 输出是否移动、变糊；
4. 纤芯信号和蜂窝图是否合理；
5. 中继倍率和传感器采样是否正确；
6. APS 是否真的是曝光积分；
7. 事件的时间、坐标和极性是否合法。

如果所有步骤隐藏在一个脚本里，只看最终结果很难判断错误来自光学模型、时间轴还是事件模拟器。

## 二、时间轴、运动与曝光

### Q3：为什么 25 ms、0.1 ms 步长会得到 251 张瞬时图，而不是 250 张？

`25 ms / 0.1 ms = 250` 表示 250 个时间区间。包含起点和终点后，时间采样为：

```text
0.0, 0.1, 0.2, ..., 24.9, 25.0 ms
```

所以共有 251 个端点样本。APS 使用这些端点做梯形积分；如果只保留 250 个点，就会漏掉曝光末端或者改变积分区间。

### Q4：25 ms 是帧周期还是曝光时间？

两者在物理上不是同一个概念。40 fps 对应 25 ms 帧周期，但真实 APS 曝光可以短于帧周期。

当前基线配置明确设置：

```yaml
motion.duration_s: 0.025
aps.exposure_start_s: 0.0
aps.exposure_end_s: 0.025
```

因此**本次仿真**恰好让整个 25 ms 序列同时作为一张 APS 的曝光窗口。这是当前实验选择，不应推广成“40 fps 必然曝光 25 ms”。

### Q5：为什么速度是 180 um/s？

当前水平位移为：

$$
180\ \mathrm{um/s}\times 0.025\ \mathrm{s}=4.5\ \mathrm{um}.
$$

它恰好等于一个标称芯间距。这样可以观察物体结构从一组纤芯采样相位移动到相邻采样相位的完整过程，便于检查运动方向、事件极性和蜂窝采样变化。

### Q6：只做水平方向移动，足以证明二维超分辨吗？

不够。水平匀速运动适合做第一轮符号和时间对齐检查，但事件主要约束运动方向上的亮度梯度，垂直方向仍可能欠约束。

要验证二维超分辨，后续至少需要加入：

- 两个不共线方向的运动；或
- 二维闭合轨迹、Lissajous 轨迹等覆盖多个采样相位的运动。

所以当前水平基线证明的是“前向链路可以产生合理 frame/event 数据”，不是“已经证明二维 NeuroSR 重建成立”。

## 三、光学和多芯光纤模型

### Q7：代码中的 GRIN 模块是真实的 GRIN 光线传播或波动光学模型吗？

不是。当前 `grin.py` 做的是：

1. 根据物体位移和放大率进行坐标重采样；
2. 使用可配置 Gaussian 模糊近似远端成像 PSF；
3. 乘一个整体透射系数。

当前 `sigma_um=0.8` 是简化的工作参数，不是由某根 GRIN 透镜的 NA、长度、折射率分布或实测 PSF 推导出来的。因此它适合链路验证，不足以声称复现了真实 GRIN 光学系统。

真实实验阶段应优先用实测 PSF、畸变图和照明平场替换该简化模型。

### Q8：纤芯是圆形，为什么又说是六角结构？

这描述的是两个不同层面：

- 单根纤芯的入口和出射斑近似圆形；
- 多根纤芯的中心位置按六角晶格排列。

当前代码使用直径 2.9 um 的圆形面积覆盖核，并按 4.5 um pitch 生成六角中心阵列，两者并不矛盾。

### Q9：为什么每根芯要做圆孔面积平均，不能只取中心像素？

真实纤芯具有有限面积，它接收的是孔径范围内的能量，而不是中心处一个无限小点的强度。只取中心像素会虚构纤芯孔径本来不能传递的高频。

当前实现先用亚像素采样构造圆形覆盖核，再对输入图做归一化圆孔平均，最后在纤芯中心读取信号。这样同时保留了：

- 有限纤芯孔径的低通作用；
- 非整数像素半径的面积覆盖；
- 六角中心的亚像素位置。

### Q10：光纤输出图中的圆斑是不是“芯间串扰”？

不是。当前流程先得到每根芯的独立标量 `core_signals`，再把这个值渲染成圆形出射斑。圆斑只是近端/出射端空间外观。

真正的芯间串扰意味着一根芯的能量耦合到邻芯信号，需要在 `core_signals` 之间加入耦合矩阵。当前代码没有实现这个过程，所以不能把出射斑的空间扩展称为芯间串扰。

### Q11：为什么只模拟 160 x 160 um，而不是完整 550 um 有效光纤面和约 15000 根芯？

局部视场足以验证圆孔采样、六角排布、运动、APS 积分和事件生成，同时显著降低 251 帧高分辨率序列的内存与运行时间。

当前 160 x 160 um 方形区域实际生成 1415 根完整落在边界内的纤芯。它是局部模型，不代表整束光纤的总芯数。

扩展到完整光纤前还需要确定：

- 550 um 有效 image circle 与 600 um 外径的区别；
- 真实 core map，而不是无限理想六角晶格；
- 边缘坏芯、增益、暗角、畸变和计算资源预算。

## 四、中继和 DAVIS 传感器

### Q12：中继倍率 30.0625 是怎么得到的？

当前光纤 ROI 是 160 um 方形，DAVIS346 是 `346 x 260`，像元尺寸为 18.5 um。`magnification: fit` 选择能让方形 ROI 完整放入传感器的较小倍率：

$$
M=\min\left(
\frac{346\times18.5}{160},
\frac{260\times18.5}{160}
\right)=30.0625.
$$

限制来自 260 像素的短边。由此得到：

- 芯间距在传感器上约为 7.3125 px；
- 芯直径在传感器上约为 4.7125 px。

这里的倍率是几何适配值，不是已标定光路的真实倍率。

### Q13：为什么中继后还要做 sensor pixel integration？

DAVIS 像元测量的是像元面积内的平均辐照度，不是像元中心的点采样。代码先在每个 sensor pixel 内建立 `2 x 2` 子像素网格，再把子像素值平均，从而近似像元面积积分。

`pixel_integration_supersample=2` 是精度和速度的折中。提高它可以做收敛测试，但不应把更高 supersample 误解为传感器分辨率提高。

### Q14：当前强度值有光子数、电子数或 DN 的绝对物理单位吗？

没有。当前链路主要使用归一化 float32 线性强度，范围大致为 `[0,1]`；输入 v2e 前才乘 `input_white_dn=255` 适配其输入约定。

因此当前 APS 没有模拟：

- 光子计数和 Poisson shot noise；
- quantum efficiency；
- read noise、dark current、PRNU；
- ADC、饱和和真实相机响应曲线。

当前结果用于验证几何、时间和相对强度变化，不用于预测真实 SNR 或曝光量。

## 五、APS 与事件生成

### Q15：APS frame 和 events 是不是从两套不同数据生成的？

不是。两者都来自同一个 `04_sensor/sensor_sequence.h5`：

```text
同一条连续 sensor irradiance sequence
  |-- 时间积分 -> APS frame
  `-- log threshold emulator -> events
```

它们共享相同的物体、运动、光纤、继像、传感器坐标和时间戳。这一点是 frame-event 联合重建具有物理一致性的前提。

### Q16：能不能先生成一张低帧率 APS，再用 v2e 或插帧生成事件？

不应该。APS 已经对曝光期间的强度做了时间积分，其中的快速变化已经丢失。从最终模糊帧再插值，只能猜测中间变化，不能恢复真实事件所携带的独立时间信息。

当前实现的正确顺序是：先从物理前向模型生成 0.1 ms 间隔的瞬时传感器序列，然后分别积分 APS、生成 events。它没有把 APS 图像重新送回 v2e，也没有使用 SuperSloMo 补帧。

### Q17：v2e 在这里负责生成 APS frame 吗？

不负责。v2e 只负责把连续强度序列转换为事件。APS 由本项目的 `integrate_aps_frame()` 单独执行梯形时间平均。

v2e 中用于展示的 event accumulation frame 只是事件计数可视化，不是光强 APS frame，二者不能互换。

### Q18：事件阈值为什么选 0.2？现在模拟的是理想事件相机吗？

`pos_threshold=neg_threshold=0.2` 与本地 v2e 的常用默认物理对数对比度阈值一致，适合作为第一轮基线，但它不是当前硬件实测标定值。

当前配置关闭了：

- threshold mismatch；
- photoreceptor cutoff；
- leak；
- shot noise；
- refractory period。

所以它是使用 v2e 阈值机制生成的近理想基线。后续应逐项开启非理想因素，而不是一次全部加入，否则很难解释事件变化来自哪个参数。

### Q19：输入步长是 0.1 ms，是否意味着已经模拟了 DAVIS 的 1 us 时间精度？

不是。0.1 ms 是前向强度序列的采样间隔。v2e 会在相邻输入帧之间为多事件分配中间时间戳，但这些时间仍由相邻强度样本和模拟器的离散策略决定，不等价于从 1 us 连续物理信号直接触发。

因此当前事件时间轴足以做第一轮同步和统计检查，但若研究高速瞬态或精确事件时间，需要继续减小 `dt_s` 并做时间步长收敛测试。

### Q20：为什么第一个事件不是在 0 ms？

事件模拟器收到第一张瞬时帧时，只用它初始化每个像素的参考 log intensity，不会立刻产生事件。只有后续亮度相对该参考累计越过阈值后，才会触发第一个事件。

当前结果的第一个事件约为 0.6 ms，这是当前图案、速度、采样和阈值共同作用的结果，不表示时间轴少了 0.6 ms。

### Q21：事件文件为什么保存两套数据集？

`events.h5` 同时保存：

- `events_t_s_x_y_p`：float32，时间单位秒，极性为 `-1/+1`；
- `events_t_us_x_y_p01`：uint32，时间单位微秒，极性为 `0/1`。

第一套便于科学计算并保留内部约定；第二套便于兼容常见事件代码。使用前必须确认下游程序要求的时间单位、列顺序和极性编码，不能只看数组有四列就直接接入。

## 六、结果与验证边界

### Q22：当前基线实际生成了什么结果？

现有输出记录为：

| 项目 | 当前结果 |
|---|---:|
| 时间区间 / 端点样本 | 250 / 251 |
| 最终位移 | `[4.5, 0.0] um` |
| 局部纤芯数 | 1415 |
| sensor sequence | `[251,260,346]` |
| APS frame | `[260,346]` |
| 事件总数 | 65745 |
| ON / OFF | 31931 / 33814 |
| 首 / 末事件 | 约 0.6 ms / 25.0 ms |

这些数字来自当前 `outputs/phase1_usaf`，改变输入裁剪、运动、阈值或 v2e 参数后都会变化。

### Q23：`all_passed=true` 是否证明仿真在物理上完全正确？

不是。当前 validation 主要检查：

- shape 和时间样本数；
- 数值是否 finite；
- 运动终点是否正确；
- 事件是否非空、按时间排序；
- 坐标、时间范围和极性是否合法。

它能发现结构、I/O 和明显数值错误，但不能证明 GRIN 参数真实、PSF 已标定、事件统计匹配硬件，或 NeuroSR 一定能成功重建。

### Q24：当前输出能直接交给 `isl_diff_event_clean/NeuroSRM_demo.py` 吗？

不能直接交给，原因至少有三点：

1. clean Demo 当前读取 AEDAT4，而这里输出 HDF5；
2. Demo 的数据选择逻辑依赖多张 APS 及其曝光时间表，这里当前只有一个仿真曝光；
3. 普通平移 IWE 假设传感器特征随运动平移，而多芯光纤近端芯位固定、变化的是各芯亮度，是否能直接使用同一运动模型需要专门验证。

接入前需要明确选择：

- 先写格式适配器，把仿真数据转换成 clean pipeline 的统一数据对象；
- 还是为多芯光纤建立 fibre-aware forward/event operator，再接入优化器。

不能为了“能读入”而忽略第三点的物理模型差异。

### Q25：当前实现与早期 core-domain 第一阶段方案冲突吗？

不必然冲突，但二者目标不同：

- core-domain 方案把每根芯当一个独立测量通道，适合先验证逆问题是否有信息增益；
- 当前 simulator 继续渲染到 DAVIS 像素并用 v2e 生成事件，适合验证更完整的传感器前向链路。

当前 `fibre_sequence.h5` 已保存 `core_signals[T,N]`，所以后续仍可以从同一条仿真中构建 core-domain 基线；`sensor_sequence.h5` 则用于 sensor-domain 压力测试。关键是实验报告必须说明使用的是哪一个观测域，不能把二者的像素数和信息量直接比较。

## 七、下一步应怎样推进

当前前向链路通过后，建议按以下顺序推进：

1. 固定当前真值运动，先完成一个可解释的重建闭环。
2. 分别建立 core-domain 和 sensor-domain baseline，确认二者的观测含义。
3. 做 frame-only、event-only、frame+event 消融，不只展示一张重建图。
4. 把水平轨迹扩展为二维轨迹，检查方向性欠约束。
5. 扫描 `dt_s` 和事件阈值，验证事件统计与重建对离散时间的稳定性。
6. 逐项加入 threshold mismatch、带宽、噪声、PSF 和 core gain，而不是同时加入。
7. 最后再替换为实测 core map、实测光学 PSF 和真实 DAVIS 标定参数。

在这些步骤完成前，当前项目最准确的表述是：**已经生成时间一致的多芯光纤 APS-event 仿真数据，但尚未完成 NeuroSR 重建闭环和真实硬件一致性验证。**
